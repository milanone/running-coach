# running-coach

Command-line analyzer for running sessions exported from [intervals.icu](https://intervals.icu).
It reads the activity CSV, computes a few training-load metrics, and keeps a local history so
each new session can be compared with the previous ones.

## Metrics

- **Efficiency Factor (EF)** — metres covered per heartbeat-per-minute (`distance_m / (avg_hr × minutes)`); higher means better aerobic efficiency.
- **Cardiac drift** — how much average heart rate rises from the first to the second half of the
  steady part of the run (%). The first 10 minutes (`WARMUP_S`) and an auto-detected final-km
  sprint are excluded. A high value points to fatigue, heat or dehydration.
- **TSS** — a training-stress score from duration and heart rate relative to threshold.
- **Altitude** — the `altitude` column as recorded (minimum and maximum of the run, change over each km), read as saved: no filter, no ascent total.

### Advanced metrics (estimates)

Computed by `run_metrics.py` from the per-second data and the history, in the spirit of what a Garmin watch reports. **They are estimates:
the vendors' algorithms are proprietary, so do not expect their numbers; read the trends.** Your maximum and resting heart rate and your
mass go in `athlete.json` in the data folder (defaults 190 bpm, 60 bpm, 70 kg), never in this repository.

- **Per run**: moving time; time in the five heart-rate zones (percent of the maximum, as Garmin's defaults) and the Edwards TRIMP;
  a 0-5 *aerobic training effect* and a *recovery time* (both **indicative**: the scale is mine, not calibrated against a Garmin);
  **VO2max estimate** (heart rate at a steady speed, ACSM running equation, heart-rate reserve taken as VO2 reserve: about +-10%);
  **pace at a fixed heart rate** and **heart rate at the usual speed** (the cleanest fitness trend: it does not depend on how hard you chose to run);
  steps per minute and step length (a CSV cadence below 120 is read as per foot and doubled); a **rough power model**
  (not a measured power); **performance condition** (efficiency of minutes 6-20 against your last ten runs); heart-rate recovery in 60 s
  (when the recording goes on after you stop) and heart-rate rise time at the start; second half against first half, kilometre-time variability;
  best efforts (fastest 1 km, 1 mile, 3, 5, 10 km, half marathon inside the run) and surges/intervals detected from the speed.
- **From the history**: *Fitness* (CTL, 42 days), *Fatigue* (ATL, 7 days) and *Form* (TSB) from the TSS; the acute/chronic load ratio
  (load of the last 7 days over the weekly average of the last 28, as Garmin states it); a training status label (a heuristic modelled on Garmin's:
  Productive, Maintaining, Recovery, Unproductive, Ramping up, Strained, Overreaching, Detraining); race predictions from the VO2max
  (Daniels-Gilbert VDOT) and from your best recent effort (Riegel, slow because training is not racing); all-time best efforts.
- Not possible with this data: ground contact time, vertical oscillation, HRV, Body Battery, sleep (they need other sensors).

The values are computed in a thread when the **Fitness** tab, or **Charts** on an advanced metric, is opened, and cached in
`run_metrics_cache.json` in the data folder (recomputed when a CSV, the merges or `athlete.json` change).

## GUI

```
py running-coach-gui.pyw        # or double-click the file (Windows opens it without a console)
```

Pick the data folder (the one with the `YYYY.MM.DD HH.MM-RUNNING.csv` files and `running_history.csv`;
it is remembered in `~/.running_coach_gui.json`), then:

- **Download new sessions from intervals.icu** fetches the per-second streams of the runs not yet in the folder
  (running only, saved as `YYYY.MM.DD HH.MM-RUNNING.csv`) and then imports them. It needs your intervals.icu API key
  (Settings → Developer Settings): put it in `intervals_api_key.txt` next to the program (gitignored) or in the
  `INTERVALS_API_KEY` environment variable.
- **Import local CSVs (legacy)** analyses only the CSVs already in the folder and not yet in the history (no download). **Reprocess all**
  recomputes every session (the weather already recorded is kept).
- **History** lists all sessions; select one to see the per-km splits, sprint note and weather.
- **Run detail** (double-click a run, or open the tab) plots every per-second column saved in the CSV for the selected run:
  speed (`velocity_smooth`, shown as km/h or as pace in min/km with the faster pace up), heart rate, cadence, and both `altitude` and
  `fixed_altitude`, against time or distance.
  Moving the mouse shows all the values of that second (with pace and GPS position).
- **Fitness** opens with the advice for the next session (rest days, distance, pace, from the TSS, the drift, the efficiency trend, the
  load ratio and your pace at a fixed heart rate), then the advanced metrics: a summary (load, status, VO2max, race predictions, best
  efforts) and a table with one row per run; select a row for its full list. The same metrics can be plotted over time in **Charts**.
- **Map** draws the GPS track of the selected run (start in green, end in red) over an OpenStreetMap map of the area, with a scale bar,
  coloured by speed (slow blue to fast red, between the 5th and 95th percentile of the run, with a legend). Drag to move, mouse wheel to zoom
  (the point under the cursor stays put), **Fit** to see the whole track again; hovering the track shows time, distance, speed and pace,
  heart rate, cadence and altitude at that point.
  The tiles are downloaded from `tile.openstreetmap.org` only while this tab is open and are cached in `~/.running_coach_tiles`
  (one run needs about 10-20 tiles). The requests carry tile numbers, not your track, but they do reveal the area you are looking at.
  Without a connection the track is drawn on a grey background. The example above is a synthetic loop, not a real run.
- **Merge runs / Unmerge runs** (right-click in the History table, select two or more runs first): merges runs recorded as
  one outing; nothing is deleted, the CSVs stay and *Unmerge runs* restores them. Merged sessions are highlighted.
- **Charts** plots distance, pace, heart rate, EF, drift or TSS over time with a 3-session moving average.

The program is the GUI (`pythonw running-coach-gui.pyw`); `parse_run_csv.py` holds the logic it uses and the history format.

**Weather lookup.** For each session it queries the [Open-Meteo](https://open-meteo.com) historical API with the **start
coordinates** of the activity to record temperature, humidity and wind. If the request fails the program continues without
weather data. Untick **Online weather** (or set `FETCH_WEATHER = False`) if you do not want coordinates sent to an external service.

## Outings recorded as several sessions

If a run was recorded as several sessions (the recording restarted after a pause), select them in the History table and use
the right-click menu **Merge runs**, or list them by hand in `merged_sessions.json`
in the data folder, the first one as the key: `{"2026.08.18 16.45": ["2026.08.18 17.21", "2026.08.18 17.38"]}`.
They are then analysed as one session starting at the first: distances and moving times add up (the pause is not
counted), and the member sessions disappear from the history. Their CSVs stay in the folder so a download does not
fetch them again. Run **Import local CSVs (legacy)** (or the download button) once to apply it.

## The history file

`running_history.csv` has one row per session with the columns `date` (dd/mm/yyyy), `time`, `dist_km`, `duration_hms`,
`pace_minkm`, `avg_hr_bpm`, `ef_m_beat`, `drift_pct`, `tss`, `temp_c`, `humidity_pct`, and `wind_kmh`.
The recommendations use only objective data (TSS, cardiac drift, EF trend); the former subjective "legs" rating was
removed. Files written by earlier versions (Italian column names such as `data`, `orario`, and the `gambe` / `legs`
column) are still read: the names are translated and the legs column is dropped the next time the history is saved.

## Configuration

Personal parameters are constants at the top of the script. Edit them to match your own values:

| Constant | Meaning |
|---|---|
| `THRESHOLD_HR` | Lactate-threshold heart rate (bpm) |
| `EF_BASELINE` | Baseline efficiency (m/beat) used as a reference |
| `FETCH_WEATHER` | Query Open-Meteo for weather (the *Online weather* box of the GUI overrides it) |
| `DRIFT_LOW`, `DRIFT_HIGH`, `DRIFT_VERY_HIGH` | Drift thresholds (%) for the "good" / "high" / "very high" messages and the rest-day and distance adjustments |
| `WARMUP_S` | Seconds excluded from the start when computing cardiac drift |
| `SPRINT_PACE_S`, `SPRINT_HR_BPM` | How much faster / higher than the median flags a sprint |

**Keeping data out of this repo.** Point the data folder box of the GUI (or the `RUNNING_COACH_DATA`
environment variable, read at start-up) at a separate folder: the activity CSVs are read from it and
`running_history.csv` is written to it — for example a private data-only repository cloned next to this one.

Body parameters for the advanced metrics (`hr_max`, `hr_rest`, `mass_kg`, optionally `cadence_factor` 1 or 2 and `hr_ref`) go in
`athlete.json` in that folder, e.g. `{"hr_max": 190, "hr_rest": 60, "mass_kg": 70}`.

## Tests

```
py -m unittest discover -s tests -v
```

`tests/synth.py` generates synthetic intervals.icu-style CSVs (doubled Samsung distance, GPS lockup
at the start, optional final-km sprint), so the logic can be checked without real data.

## Privacy

This repository contains code only. `.gitignore` excludes `*.csv`, `*.fit`, `*.tcx`, `*.gpx`
and `running_history.csv`, so activity exports, GPS tracks and your history never get committed.
Keep your own data files out of version control.

## Requirements

Python 3, standard library only (the charts are drawn on a Tkinter canvas, without matplotlib). The GUI needs Tkinter, which ships with the standard Python
installer on Windows and macOS (Linux: `sudo apt install python3-tk`).
